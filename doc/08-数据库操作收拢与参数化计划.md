# 08 数据库操作收拢与参数化计划

> 状态：已批准待执行。
> 背景：数据库操作代码质量审查（2026-09-12）发现：SQL 主体已集中在 `internal/store/sqlite/`（78 处，全部 `?` 占位参数化），但 **backup 导入把上传 zip 内 `db.sqlite3` 的表结构引入动态 SQL 标识符**（防御缺口，优先修复），且少量 SQL 越层散落在 service。本计划对齐 element-skin 的「SQL 只存在于 database 层」边界，同时保留 element-wiki 自身的窄接口注入设计。

## 审查结论（计划的事实基础）

### 现状分布（非测试代码）

| 位置 | SQL 调用数 | 评价 |
|---|---|---|
| `internal/store/sqlite/`（16 文件） | 78 处 | ✅ 正确位置，全部参数化 |
| `internal/service/backupservice/service.go` | 7 处 | ⚠️ 越层持 `*sql.DB` |
| `internal/service/docservice/service.go` | 0 处生产 SQL | ⚠️ `rawDB any` 弱类型测试桥（service.go:33） |
| `internal/httpapi/` | 0 处 | ✅ 干净（grep 命中均为 `r.URL.Query()`） |
| `internal/database/database.go` | 0 处 | ✅ 纯连接工厂 + PRAGMA |

### 参数化审查结论

- 普通业务路径（HTTP 输入 → SQL）：**全部参数化，无注入漏洞**。store 层所有 `WHERE`/`VALUES` 均为 `?` 占位；无 LIKE 拼接进 SQL 文本的用法。
- 三处动态 SQL 集中在 backupservice：
  1. `DELETE FROM `+tbl``：tbl 来自代码内硬编码白名单 `dataTableOrder`，当前安全，形式违规。
  2. `WHERE id <> '" + selfID + "'"`（service.go:322）：selfID 为服务端生成的 job ULID，非用户输入，当前安全；**字符串拼 SQL 形式违规，必须改 `?` 占位**。
  3. `fmt.Sprintf("INSERT INTO %s (%s) VALUES (%s)", table, strings.Join(cols, ","), placeholders)`（copyTable，service.go:392）：**`cols` 来自上传 zip 内 db.sqlite3 的 `rows.Columns()`**——外部文件的实际 schema 进入 SQL 标识符。即使上传仅限 admin（受信任面），也不能视为可信输入。这是本计划最高优先级修复项。
- element-skin 对照：其模糊查询用 `$1` 传 `"%"+query+"%"`（模式值参数化、模式拼接不进 SQL 文本），标识符全部来自代码内常量——即「值永远走参数、标识符永远来自代码」原则。

### 与 element-skin 的对齐边界

| 维度 | element-skin | 本计划采纳 |
|---|---|---|
| SQL 安放 | 全部在 `internal/database/<域>/`，service/httpapi 零 SQL | ✅ 采纳（收拢目标） |
| store 组织 | 按域子包，每域多文件 | ✅ 采纳（阶段 3 目录迁移） |
| service 持 DB | service 直接持 `*database.DB` 聚合 | ❌ 不采纳——保留 wiki 现有窄接口注入（利于测试替身与依赖隔离，符合 AGENTS §3） |
| schema 管理 | Go 代码 `InitSQL` 常量 | ❌ 不采纳——保留嵌入式迁移 + 版本校验（双方言） |

## 目标结构（阶段 3 完成后）

```text
internal/database/
  db.go                  连接工厂（自 internal/database/database.go 平移）
  contracts.go           各域 store 接口（自 internal/store/store.go 拆分迁入）
  user/                  users/sessions/api_tokens
  document/              documents/tree（含 slug、可见性解析）
  commit/                document_blobs/document_commits/document_drafts
  comment/               comments/comment_mentions
  attachment/            attachments
  setting/               settings
  job/                   search_reindex_jobs/backup_jobs/import_jobs
  stats/                 仪表盘聚合
  backup/                VACUUM INTO / 整库替换 / 跨库拷贝（自 backupservice 收拢）
  sqlite/                双方言公共 helper（mapErr/scan/nowMs 等）
migrations/              不变（嵌入式 SQL 迁移，双方言分目录）
```

- `internal/store/` 与 `internal/store/sqlite/` 迁移完成后删除。
- service 层接口 import 路径改为 `internal/database/<域>`；httpapi 不感知任何变化。

## 阶段 1 · backup 导入注入面修复（最高优先级，独立提交可先行）

### 改动

`internal/service/backupservice/service.go`：

1. `selfID` 拼接改参数化：`DELETE FROM backup_jobs WHERE id <> ?` / `DELETE FROM import_jobs WHERE id <> ?`（删除 `extra` 字符串拼接分支）。
2. 表名白名单收敛为单一常量来源：`dataTableOrder` 与操作表清单合并为不可变声明（`var` → 函数内只读或加注释锁定），并加 `^[a-z_]+$` 断言防御（防未来有人把外部输入接进来）。
3. **`copyTable` 不再信任上传库 schema**：
   - 为 9 张数据表 + 5 张操作表定义**代码内固定列清单**（与 doc/01 DDL 一一对应，含列序）；
   - 导入前逐表校验：上传库实际列集合与固定清单**完全一致**（多列/少列/列名不符/列序不符均整体失败，错误归类 `ErrBadManifest` 语义）；
   - INSERT 语句的表名与列名一律取自代码内固定清单，`rows.Columns()` 仅用于校验比对；
   - `SELECT` 侧同样按固定列名显式列出（不再 `SELECT *`）。
4. 表存在性容错（"no such table" 跳过）语义保留，但跳过仅允许对可选表（操作表），数据表缺失即失败。

### 测试

- 恶意 schema 备份用例：上传库 documents 表多一列 `evil TEXT`、列名含注入形态（如 `` comment`--x ``）、列序颠倒 → 均整体失败且主库零污染（断言导入前后各表行数不变）。
- 缺表用例：上传库缺 `comments` → 失败；缺 `backup_jobs`（可选表）→ 跳过成功。
- 既有导入成功/零残留测试保持绿。
- `selfID` 参数化回归：导入保留自身 job 行的既有断言不回退。

### 验收

- `grep -n '" + selfID' internal/service/backupservice/service.go` 零命中。
- 恶意 schema 测试全绿；`go test ./internal/service/backupservice/` 全绿。

## 阶段 2 · backup SQL 收拢到 database 层

### 改动

1. 新建 `internal/database/backup/`：
   - `Snapshot(ctx, dstPath)`：`VACUUM INTO ?`；
   - `CountAliveDocuments(ctx)`：导出统计（现 runExport 内 QueryRow）；
   - `ReplaceAll(ctx, srcPath, selfJobID)`：打开 staged 库 → 单事务清空+拷贝（含阶段 1 的固定列清单与校验逻辑，全部随迁）；
   - 实现持 `*sql.DB`（SQLite 专用能力，接口注释标注「仅 SQLite 方言实现；PG 路径走 pg_dump/restore 另行立项」）。
2. `internal/store/store.go` 新增 `BackupStore` 接口（或独立 `database/backup/contract.go`），backupservice 改持接口。
3. `backupservice.Service` 删除 `live *sql.DB` 字段与 `sql.Open("sqlite", staged)` 直连；`runExport/runImport` 只编排 zip、附件目录交换、job 状态与重建钩子。
4. main 装配点同步（cmd/wikid/main.go:115）。

### 测试

- backup 测试改为经 database 层注入替身/临时库；既有导出下载、导入零残留、PG 501 降级测试全绿。
- 分层守门：`grep -rn "database/sql" internal/service/ --include="*.go" | grep -v _test` 仅允许 docservice 测试桥过渡期命中（阶段 3 清零）。

### 验收

- backupservice 全文件无 `database/sql` import、无 `ExecContext/QueryContext`。
- `go test ./...` 全绿。

## 阶段 3 · store → database 域子包迁移（最大改动，逐域提交）

### 改动

1. 按目标结构逐域迁移：接口定义 + sqlite 实现同域同迁（`documents.go`+`tree.go` → `document/`；`commits.go`+`drafts.go` → `commit/`；`users.go`+`sessions.go`+`tokens.go` → `user/`；以此类推）。
2. 双方言公共 helper（`mapErr`/`scanDoc`/`nowMs`/`newIDForJobs`）落 `internal/database/sqlite/`（或 `database/internal/`），域包引用。
3. `docservice.rawDB any` 与 `RawDBForTest` 删除：
   - 测试断言（污染路径检查、孤儿文件检查）改走 store 接口读数或测试内自建 sqlite 连接（测试包允许直连，生产代码不允许）；
   - `CountAliveForTest` 改为测试内直接调 `ListAliveIDs`。
4. `internal/store/`、`internal/store/sqlite/` 删除；全仓 import 路径更新。
5. mdimport/backupservice 的 `m.Svc.FindBySlug` 等复用不变（service 间调用，与 store 迁移无关）。

### 测试

- 纯机械迁移 + import 重写，行为零变化：`go test ./...` 全绿即验收。
- 每域一个提交（user → document → commit → comment/attachment → setting/job/stats → backup 收尾），便于回滚。

### 验收

- `ls internal/store` 不存在；`grep -rn "internal/store" --include="*.go" .` 零命中。
- 覆盖率不低于基线 79.5%。

## 风险与备注

- 阶段 1 是安全修复，独立提交可先行合入，不依赖后续阶段。
- 阶段 3 为大规模机械迁移：接口与实现同域同迁、每域一提交；迁移期间 `internal/store` 与 `internal/database` 短暂并存，门禁（阶段 4）在迁移全部完成后才启用。
- SQLite 专用能力（VACUUM INTO / ATTACH）在 database/backup 接口注释中显式标注方言约束；PG 备份路径本就 501 降级（C6），不引入新契约。
- 阶段 1/2 涉及 backup 核心链路，失败路径测试（零残留、零污染）必须先补恶意 schema 用例再动代码。
- 全程不动 doc/01/02 契约（无端点/表结构变更）；若阶段 3 迁移中发现接口语义需调整，停下走契约变更流程。

## 收尾门禁

- `go test ./...`、`go vet ./...` 全绿；总覆盖率不低于 79.5% 基线。
- 守门 grep 全部零命中：
  - `internal/service`、`internal/httpapi` 非测试代码无 `database/sql`；
  - 全仓非测试代码无 `ExecContext|QueryContext|QueryRowContext|PrepareContext`（`internal/database/` 除外）；
  - 全仓无 `internal/store` 引用残留。
- 恶意 schema 导入测试在套件中长期存在。
- `doc/ROADMAP.md` 登记本计划条目与完成状态；AGENTS.md §2 目录说明同步。
