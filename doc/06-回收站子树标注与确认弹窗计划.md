# 06 回收站子树标注与确认弹窗计划

> 状态：已批准待执行（前端小改，无后端/契约变更）。
> 背景：M18 后恢复/彻底删除的实际作用范围均为「该条目 + 回收站内子孙」的子树，但 TrashView 平铺展示无子树归属标识、彻底删除无确认弹窗——用户无法预判按钮影响范围（明确选型：1 子树标注 + 2 确认弹窗；树形嵌套展示明确不做）。

## 背景与问题

- `ListTrash` 返回所有 trashed 行（含每个子孙），TrashView 平铺为 N 行：回收「父 + 3 子」显示 4 行，行间无任何子树归属信息。
- 「彻底删除」点击即物理删除（不可逆），**无确认弹窗**，且 `purge()` 无 try/catch（失败会触发未处理 Promise 拒绝）。
- 语义本身不变（已实现并有测试）：
  - 恢复：该条目 + 回收站内子孙 → 「已恢复」容器（M18）
  - 彻底删除：该条目 + 回收站内子孙 → 物理删除

## 方案（仅前端）

### 1. 子树标注

- `TrashItem` 已含 `parent_id`，前端由平铺列表推导归属，不做树形嵌套：
  - 行的 `parent_id` 命中列表内另一行 → 该行标注 badge「随父级一并处理」
  - 行下存在子孙（由其余行的 `parent_id` 链回溯）→ 该行标注 badge「含 N 个子项」
- 展示形态：标题右侧小号灰字 badge（`text-xs text-gray-400`），不缩进、不改行序。
- 边界：父行被单独恢复/彻底删除后，子行 `parent_id` 不再命中列表 → badge 自动消失，子行成为独立子树根（行为自然正确，无需特判）。

### 2. 彻底删除确认弹窗

- `ElMessageBox.confirm`（`type: 'warning'`）：
  - 文案：`将彻底删除「{title}」{子句}，不可恢复。确定继续吗？`
  - 子句：N > 0 时为 `及其回收站内 {n} 个子文档`，N = 0 时为空
- 确认后才调用 `trashApi.purge`；取消 → 不发请求、列表不变。
- 顺手修复：`purge()` 包 try/catch，失败 `ElMessage.error(t('trash.purgeFailed'))`，消除未处理拒绝。
- 「恢复」按钮不加弹窗（明确排除；M18 已有「已恢复到『已恢复』目录」的成功提示）。

### 3. i18n（zh / en 同步，key parity 测试守护）

| key | zh-CN | en |
|---|---|---|
| `trash.subtreeChild` | 随父级一并处理 | Part of a trashed subtree |
| `trash.subtreeCount` | 含 {n} 个子项 | Includes {n} sub-items |
| `trash.purgeConfirm` | 将彻底删除「{title}」{detail}，不可恢复。确定继续吗？ | Permanently delete "{title}" {detail}? This cannot be undone. Continue? |
| `trash.purgeConfirmDetail` | 及其回收站内 {n} 个子文档 | and {n} trashed sub-items |
| `trash.purgeFailed` | 彻底删除失败 | Failed to delete permanently |

## 测试计划（TrashView.spec.ts）

1. 子树标注：父行渲染「含 1 个子项」、子行渲染「随父级一并处理」；无子孙的独立行无 badge。
2. purge 确认：点「彻底删除」→ 弹窗出现且文案含标题与子项数；mock 确认 → `trashApi.purge` 以该 id 调用；mock 取消 → 不调用且列表不变。
3. purge 失败：mock 拒绝 → 错误提示、列表刷新不崩。
4. 恢复回归：不弹确认、成功提示、列表刷新（M18 行为保持）。
5. 列表失败 → 错误态 + 重试（既有行为保持）。

## 验收标准

- 回收「父 + 子」→ 父行与子行均可见对应 badge。
- 点父行「彻底删除」→ 弹窗文案含「及 1 个子文档」→ 确认后两行消失；点独立叶子行 → 弹窗无子项子句。
- 取消 → 列表不变、零网络请求。
- `npm test` 全绿、`npm run build` 通过。

## 风险与备注

- 子项计数基于当前列表快照；并发下（他人同时 purge）计数可能与实际处理数有出入——弹窗文案以「回收站内」限定，语义可接受。
- 无后端改动、无契约变更（列表字段已含 `parent_id`）；树形嵌套展示明确不做。
- ROADMAP 登记（M19 或并入既有里程碑）随执行 commit 完成，本计划文档不含。
