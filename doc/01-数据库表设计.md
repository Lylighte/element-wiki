# 数据库表设计

> Element Wiki 使用**单库统一 schema**，SQLite 为默认实现，PostgreSQL 为可选后端。
> 所有 DDL 必须在两种方言下语义一致。

## 1. 通用约定

- 主键 ID：`TEXT`，使用 ULID（时间有序，可直接按 id 排序）。
- 时间字段：`BIGINT`，Unix 毫秒时间戳；可空时间用 `NULL` 表达状态，不引入 BOOLEAN 列。
- 枚举字段：`TEXT` + `CHECK IN (...)`。
- 列名 `snake_case`；核心业务数据一律拆列，禁止 JSON 字符串承载业务状态。
- 每个 schema 变更以迁移文件提交，运行时校验 `schema_migrations` 最大版本与二进制内置版本一致。
- 部分唯一索引（partial unique index）SQLite ≥3.8 与 PostgreSQL 均支持，可安全使用。

## 2. 迁移与版本

### 2.1 schema_migrations

CREATE TABLE schema_migrations (
    version    INTEGER PRIMARY KEY,
    name       TEXT NOT NULL,

## 3. 身份与会话

系统无本地注册/密码。用户仅通过 OIDC JIT 创建；admin 由配置 `oidc.admin_emails` 在首次匹配登录时提升。

### 3.1 users

```sql
CREATE TABLE users (
    id            TEXT PRIMARY KEY,
    issuer        TEXT NOT NULL,             -- OIDC issuer URL
    subject       TEXT NOT NULL,             -- OIDC sub claim
    email         TEXT NOT NULL DEFAULT '',
    display_name  TEXT NOT NULL,
    role          TEXT NOT NULL CHECK(role IN ('viewer','editor','admin'))
                  DEFAULT 'viewer',
    status        TEXT NOT NULL CHECK(status IN ('active','disabled'))
                  DEFAULT 'active',
    created_at    BIGINT NOT NULL,
    last_login_at BIGINT NOT NULL DEFAULT 0
);
CREATE UNIQUE INDEX idx_users_issuer_subject ON users(issuer, subject);
```

说明：

- 身份锚点是 `(issuer, subject)`；email 仅作展示与引导匹配（service 层做小写比较），不加 UNIQUE，避免邮箱变更导致 JIT 冲突。
- `status='disabled'` 的账号在认证中间件处直接拒绝；管理员禁用后该用户重新登录不会复活为新账号，而是保持 disabled 并提示联系管理员。
- 无 `password_hash` 字段——本项目不存在本地密码体系。

### 3.2 sessions

```sql
CREATE TABLE sessions (
    token_hash TEXT PRIMARY KEY,              -- SHA-256(cookie 值)
    user_id    TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    expires_at BIGINT NOT NULL,
    created_at BIGINT NOT NULL
);
CREATE INDEX idx_sessions_expires ON sessions(expires_at);
```

后台清理任务定期删除过期行。

### 3.3 api_tokens

```sql
CREATE TABLE api_tokens (
    id           TEXT PRIMARY KEY,
    user_id      TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    name         TEXT NOT NULL,               -- 用户自定义标签
    prefix       TEXT NOT NULL,               -- 明文 token 前 8 位，用于列表识别
    token_hash   TEXT NOT NULL,               -- SHA-256(完整 token)
    created_at   BIGINT NOT NULL,
    last_used_at BIGINT NOT NULL DEFAULT 0,
    revoked_at   BIGINT                       -- NULL = 有效
);
CREATE UNIQUE INDEX idx_api_tokens_hash ON api_tokens(token_hash);
CREATE INDEX idx_api_tokens_user ON api_tokens(user_id);
```

明文 token 仅在创建响应中出现一次。认证中间件将 `Authorization: Bearer` 解析为与 session 相同的 actor。

## 4. 文档与版本

### 4.1 documents

```sql
CREATE TABLE documents (
    id             TEXT PRIMARY KEY,
    parent_id      TEXT REFERENCES documents(id),
    space_id       TEXT,                      -- 预留列，v1 恒为 NULL
    slug           TEXT NOT NULL,             -- [a-z0-9-]+，父级内唯一
    title          TEXT NOT NULL,
    sort_key       INTEGER NOT NULL DEFAULT 0,
    visibility     TEXT NOT NULL CHECK(visibility IN ('standard','restricted'))
                   DEFAULT 'standard',
    head_commit_id TEXT NOT NULL DEFAULT '',  -- 见下方说明
    created_by     TEXT NOT NULL REFERENCES users(id),
    updated_by     TEXT NOT NULL REFERENCES users(id),
    created_at     BIGINT NOT NULL,
    updated_at     BIGINT NOT NULL,
    deleted_at     BIGINT,                    -- NULL = 未删除；回收站标记
    deleted_by     TEXT,
    purge_at       BIGINT                     -- = deleted_at + 保留期，清理任务依据
);

-- 父级内 slug 唯一；已进回收站的文档释放 slug
CREATE UNIQUE INDEX idx_documents_slug
    ON documents(COALESCE(parent_id,''), slug)
    WHERE deleted_at IS NULL;
CREATE INDEX idx_documents_deleted ON documents(purge_at) WHERE deleted_at IS NOT NULL;
CREATE INDEX idx_documents_parent ON documents(parent_id);
```

说明：

- **循环外键规避**：`documents.head_commit_id → document_commits.id` 与 `document_commits.document_id → documents.id` 互指。为避免双向外键的建表顺序问题，`head_commit_id` 不声明外键，一致性由 service 层在同一事务内保证。空文档允许 `''`（尚无 commit）。
- COALESCE 索引表达式使根文档（parent_id NULL）也参与唯一性约束；两种方言均支持表达式索引。
- 删除是子树操作：service 将整棵子树的 `deleted_at/purge_at` 写齐，恢复同理。

### 4.2 可见性继承

`visibility` 只存"自身设置"，生效值沿祖先链解析：

```sql
-- effective_visibility：自身或任一祖先为 restricted 则 restricted
WITH RECURSIVE ancestors AS (
    SELECT id, parent_id, visibility FROM documents WHERE id = ?
    UNION ALL
    SELECT d.id, d.parent_id, d.visibility
    FROM documents d JOIN ancestors a ON d.id = a.parent_id
)
SELECT MAX(CASE WHEN visibility = 'restricted' THEN 1 ELSE 0 END) FROM ancestors;
```

递归 CTE 在 SQLite 与 PostgreSQL 均原生支持。万级规模无需物化路径。

### 4.3 document_blobs

```sql
CREATE TABLE document_blobs (
    hash       TEXT PRIMARY KEY,              -- SHA-256 hex，内容寻址去重
    content    TEXT NOT NULL,
    size       INTEGER NOT NULL,
    created_at BIGINT NOT NULL
);
```

### 4.4 document_commits（不可变）

```sql
CREATE TABLE document_commits (
    id               TEXT PRIMARY KEY,
    document_id      TEXT NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
    commit_no        INTEGER NOT NULL,        -- 文档内从 1 单调递增
    parent_commit_id TEXT,                    -- 首 commit 为 NULL
    blob_hash        TEXT NOT NULL REFERENCES document_blobs(hash),
    author_id        TEXT NOT NULL REFERENCES users(id),
    message          TEXT NOT NULL DEFAULT '',
    created_at       BIGINT NOT NULL,
    CONSTRAINT uq_commits_doc_no UNIQUE(document_id, commit_no),
    CONSTRAINT uq_commits_doc_id UNIQUE(document_id, id)
);
CREATE INDEX idx_commits_doc_no ON document_commits(document_id, commit_no DESC);
```

说明：

- 行永不 UPDATE/DELETE（版本上限裁剪除外）。
- `uq_commits_doc_id` 用于把 HEAD 引用安全地钉在同文档内。
- **版本裁剪**（DM-07）：新 commit 落库后若 `COUNT > max_versions(默认100)`，同事务删除最旧 N 行 commits；blob 不立即删，由 GC 任务回收。

### 4.5 blob 回收

```text
GC 任务（低频后台）：
DELETE FROM document_blobs
WHERE hash NOT IN (SELECT DISTINCT blob_hash FROM document_commits);
```

草稿内容不引用 blob 表（草稿直接存文本），因此该查询天然安全。

### 4.6 document_drafts

```sql
CREATE TABLE document_drafts (
    document_id    TEXT NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
    user_id        TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    base_commit_id TEXT NOT NULL,
    content        TEXT NOT NULL,
    updated_at     BIGINT NOT NULL,
    PRIMARY KEY(document_id, user_id)
);
```

每用户每文档最多一份草稿，自动保存即 UPSERT。

## 5. 协作

### 5.1 comments

```sql
CREATE TABLE comments (
    id          TEXT PRIMARY KEY,
    document_id TEXT NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
    author_id   TEXT NOT NULL REFERENCES users(id),
    content     TEXT NOT NULL,                -- Markdown 源码
    created_at  BIGINT NOT NULL
);
CREATE INDEX idx_comments_doc ON comments(document_id, created_at);
```

删除为硬删除（审计日志已延后至二期）；权限：作者本人或 admin。

### 5.2 comment_mentions

```sql
CREATE TABLE comment_mentions (
    comment_id TEXT NOT NULL REFERENCES comments(id) ON DELETE CASCADE,
    user_id    TEXT NOT NULL REFERENCES users(id),
    PRIMARY KEY(comment_id, user_id)
);
```

service 在创建评论时解析 @提及并写入；通知能力二期再议，本期仅作数据记录。

## 6. 附件

```sql
CREATE TABLE attachments (
    id           TEXT PRIMARY KEY,
    document_id  TEXT NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
    filename     TEXT NOT NULL,
    storage_path TEXT NOT NULL,               -- 存储根目录下的相对路径
    mime_type    TEXT NOT NULL,
    size         INTEGER NOT NULL,
    sha256       TEXT NOT NULL,
    uploaded_by  TEXT NOT NULL REFERENCES users(id),
    created_at   BIGINT NOT NULL
);
CREATE INDEX idx_attachments_doc ON attachments(document_id);
```

文件本体落文件系统（`storage/attachments/<document_id>/`），先临时文件后受控提交；DB 插入失败必须删除已落盘文件。

## 7. 设置

```sql
CREATE TABLE settings (
    key        TEXT PRIMARY KEY,
    value      TEXT NOT NULL,                 -- 标量字符串，类型由 config 层解析
    updated_at BIGINT NOT NULL,
    updated_by TEXT
);
```

种子键：`wiki_title / anonymous_read / comments_enabled(默认 false) / max_versions / upload_max_mb / allowed_extensions / timezone / default_lang / trash_retention_days`。

## 8. 后台任务

### 8.1 search_reindex_jobs

```sql
CREATE TABLE search_reindex_jobs (
    id          TEXT PRIMARY KEY,
    document_id TEXT,                          -- NULL = 全量重建
    reason      TEXT NOT NULL CHECK(reason IN
                ('update','delete','restore','manual','corrupt')),
    status      TEXT NOT NULL CHECK(status IN ('pending','running','done','failed'))
                DEFAULT 'pending',
    attempts    INTEGER NOT NULL DEFAULT 0,
    last_error  TEXT,
    created_at  BIGINT NOT NULL,
    finished_at BIGINT
);
```

commit 成功后的同步索引更新失败时插入本表；worker 循环消费。

### 8.2 backup_jobs 与 import_jobs

```sql
CREATE TABLE backup_jobs (
    id          TEXT PRIMARY KEY,
    kind        TEXT NOT NULL CHECK(kind IN ('export','import')),
    filename    TEXT,                          -- export 完成后的产物名
    status      TEXT NOT NULL CHECK(status IN ('pending','running','done','failed'))
                DEFAULT 'pending',
    requested_by TEXT NOT NULL REFERENCES users(id),
    last_error  TEXT,
    created_at  BIGINT NOT NULL,
    started_at  BIGINT,
    finished_at BIGINT
);

CREATE TABLE import_jobs (
    id            TEXT PRIMARY KEY,
    status        TEXT NOT NULL CHECK(status IN ('pending','running','done','failed'))
                  DEFAULT 'pending',
    total_files   INTEGER NOT NULL DEFAULT 0,
    imported_files INTEGER NOT NULL DEFAULT 0,
    failed_files  INTEGER NOT NULL DEFAULT 0,
    requested_by  TEXT NOT NULL REFERENCES users(id),
    last_error    TEXT,
    created_at    BIGINT NOT NULL,
    started_at    BIGINT,
    finished_at   BIGINT
);
```

两者共用同一套异步 job 执行器。import 失败必须整体回滚：不留半导入文档、不留孤儿附件、不写索引任务。

## 9. 设计决策记录

| 决策 | 理由 |
|------|------|
| 死链检测结果**不入库** | 只需出现在 commit 响应与编辑页；持久化会引入同步负担，读时由 service 从当前 blob 解析即可 |
| `head_commit_id` 不加外键 | 规避 documents↔commits 双向 FK 建表环；事务内一致性由 service 保证并测试覆盖 |
| blob 内容存 DB 而非文件系统 | Markdown 体量小；换取跨存储事务简化与备份原子性（备份=单 DB 文件+attachments 目录） |
| 评论硬删除 | 审计延后二期；版本历史才是内容事实来源 |
| 无独立 roles 表 | 三档模板是常量映射，入库反而诱导运行时角色扩张；权限码目录见 API 设计文档 |
