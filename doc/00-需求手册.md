# Element Wiki 需求手册 v0.2（冻结基线）

> 项目定名 **Element Wiki**，以 MIT 协议发布。
> 工程标准遵守 LabProject AGENTS.md；架构借鉴 LabProject 已有设计，功能范围参考 wiki-go 思路但不使用其代码。

## 0. 产品定位与原则

- 自托管团队/个人知识库，目标规模：万级文档、百级用户
- 零依赖起步：单二进制 + 单 SQLite 文件即可运行；PostgreSQL 为可选规模化后端
- 身份认证完全依赖外部 OIDC Provider（Provider 故障导致锁死的风险已被接受，不留应急后门）
- 内容结构按本项目自身模型编排，不兼容任何既有 wiki 的目录格式

## 1. 架构

| 编号 | 需求 |
|------|------|
| AR-01 | Go + net/http，httpapi/service/store 三层，handler 无业务逻辑 |
| AR-02 | SQLite 默认存储，存储层接口化，PostgreSQL 可选后端 |
| AR-03 | Bleve 内嵌全文索引；索引为派生数据，可全量重建 |
| AR-04 | 单二进制，首启自动建 schema 并校验引导配置 |
| AR-05 | 支持 `base_path` 子路径部署、反代友好、原生 TLS 可选 |

## 2. 文档模型与版本

| 编号 | 需求 |
|------|------|
| DM-01 | 单棵层级文档树（目录无限嵌套），面包屑 + 侧栏树；`documents.space_id` 可空列预留多空间演进 |
| DM-02 | 文档 = 数据库元数据行 + Markdown 正文 blob；slug 父级内唯一 |
| DM-03 | `sort_key` 字段显式排序 |
| DM-04 | 线性版本模型：HEAD / commit / blob / draft，版本不可变，回滚 = 新增 commit |
| DM-05 | 按用户隔离的自动保存草稿 |
| DM-06 | 并发保存冲突返回 409，且 HEAD/blob/草稿/索引不被污染 |
| DM-07 | 版本上限可配，默认保留 100 版，超限裁剪最旧 |
| DM-08 | 回收站：软删除（`deleted_at`），支持恢复与彻底删除；后台任务按保留期（默认 30 天）自动清理 |

## 3. Markdown 渲染

| 编号 | 需求 |
|------|------|
| RD-01 | goldmark + GFM：表格、任务清单、删除线 |
| RD-02 | 代码高亮 + 复制按钮 |
| RD-03 | KaTeX 数学公式、Mermaid 图表 |
| RD-04 | TOC 自动生成 + 标题锚点 |
| RD-05 | wikilink `[[文档]]`：保存时解析并检测死链，编辑页提示 |
| RD-06 | GFM Alert（`> [!NOTE]` 等 GitHub 同款提示块） |
| RD-07 | 服务端渲染 + 输出消毒防 XSS |

## 4. 编辑器（Tiptap 2）

| 编号 | 需求 |
|------|------|
| ED-01 | Tiptap 2（ProseMirror），按场景懒加载；只读页面零加载编辑器代码 |
| ED-02 | 分屏预览 + 滚动同步 |
| ED-03 | 精简工具栏：粗斜体 / 标题 / 链接 / 图片 / 表格 / 代码块 |
| ED-04 | 表格编辑：行列增删、移动、对齐 |
| ED-05 | 快捷键 ≤10 个：Ctrl+S/B/I/K、Ctrl+E、Esc |
| ED-06 | 粘贴剪贴板图片直接上传为附件 |
| ED-07 | `[[` 触发文档标题自动补全（对接 RD-05） |

## 5. 搜索

| 编号 | 需求 |
|------|------|
| SE-01 | Bleve + CJK 分析器，中文开箱可用 |
| SE-02 | 保存后同步更新索引；失败写重建任务后台补偿；管理端手动全量重建入口 |
| SE-03 | 权限过滤在 service 层，结果返回前二次校验 |
| SE-04 | 相关度排序 + 高亮摘要 |
| SE-05 | 查询语法一期仅：关键词 + `"精确短语"` |

## 6. 认证与权限（仅 SSO）

| 编号 | 需求 |
|------|------|
| PM-01 | 登录方式仅有 OIDC（授权码流 + PKCE + nonce）；不存在本地密码、bcrypt、登录封禁模块 |
| PM-02 | JIT 自动建号：首次 SSO 登录成功即创建账号 |
| PM-03 | 引导机制：配置 `oidc.admin_emails` 列表，首个邮箱匹配的登录者获得 admin；无应急恢复通道（风险已接受） |
| PM-04 | 全局权限三档模板 viewer / editor / admin，管理面板下拉指派；内部以权限码 `resource.action.scope` 实现，禁止角色名硬编码判断 |
| PM-05 | 文档可见性两档：standard（登录可见）/ restricted（editor 及以上可见）；沿目录树向下继承 |
| PM-06 | 匿名只读模式可配（公开知识库场景），默认开启强制登录 |
| PM-07 | id_token 校验通过后换发本地 session cookie；`SECURE_COOKIES` 可配 |

## 7. 协作

| 编号 | 需求 |
|------|------|
| CO-00 | 评论系统**默认全局禁用**；admin 可在设置面板开启（`comments_enabled`），禁用期间前后端均不暴露评论功能 |
| CO-01 | 评论：Markdown 格式、线性列表、支持 @提及（提及解析到 SSO 用户） |
| CO-02 | 删除权限：admin 或评论作者本人 |

## 8. 附件

| 编号 | 需求 |
|------|------|
| AT-01 | 扩展名白名单 + 大小限制可配 |
| AT-02 | 先写临时文件 → 校验 → 受控提交；任何失败不留孤儿文件 |
| AT-03 | 按文档目录隔离存放；编辑器内一键插入引用 |

## 9. 管理与运维

| 编号 | 需求 |
|------|------|
| OP-01 | 设置面板：站点名 / logo / favicon / 时区 / 上传限制 / 匿名只读开关 / 评论开关 |
| OP-02 | 用户管理 UI：SSO 用户列表 + 三档角色指派（无建号、无改密操作）；支持禁用账号 |
| OP-03 | 备份：zip 全量（DB + 附件 + 配置）；导入前校验 manifest / schema_version / 路径安全，失败无残留 |
| OP-04 | 内容导入：通用 Markdown zip 包，zip 内目录结构直接映射为本项目文档树 |
| OP-05 | 仪表盘：文档总数 / 最近更新 / 活跃贡献者 |
| OP-06 | sitemap.xml 自动生成 |

## 10. 前端体验

| 编号 | 需求 |
|------|------|
| UX-01 | Vue 3 + TS + Vite + Element Plus + Tailwind，组件分层遵循 AGENTS.md |
| UX-02 | 响应式布局 + 暗色主题 |
| UX-03 | i18n 框架，首批仅 zh-CN + en |
| UX-04 | 打印优化样式 |
| UX-05 | 全局快捷键：Ctrl+Shift+F 聚焦搜索、Esc 关闭弹层 |

## 11. API

| 编号 | 需求 |
|------|------|
| API-01 | `/v1` 前缀、cursor 分页、`{"detail": ...}` 错误结构、稳定响应契约 |
| API-02 | REST 全覆盖：文档 CRUD / 版本 / 搜索 / 评论 / 附件 / 设置 |
| API-03 | 个人 Access Token：设置页生成/吊销，用于脚本与自动化调用 |

## 12. 非功能

| 编号 | 需求 |
|------|------|
| NF-01 | 后端测试覆盖率 ≥90%，错误路径断言事实来源无污染 |
| NF-02 | 性能目标：万级文档搜索 P95 < 200ms；文档页渲染 < 50ms |
| NF-03 | 结构化日志；GitHub Actions CI（构建 + 测试 + 覆盖率门禁） |
| NF-04 | 数据库 schema_version 迁移机制 |
